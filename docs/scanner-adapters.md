# Scanner adapters

`app/scanners.py` owns process execution and RustScan/Nmap/Gobuster parsing. It invokes tools without a shell; its guardian and children share a process group. Output is read incrementally with an 8 MiB cap and run-control heartbeat callbacks. RustScan, Nmap and Gobuster have no subprocess deadline; finite deadlines remain available for auxiliary tools. Timeout, interruption and nonzero exits become stage item failures; checkpointing is owned by the pipeline. The worker image pins RustScan 2.4.1 and EyeWitness commit `c3286fb71406e0b55b85a7c38dac76ee50b0f955`; Nmap and Chromium come from Debian security repositories.

RustScan receives one numeric address per invocation, normalized approved TCP ports, greppable output, no script execution, a configurable connection batch (`max_threads`), one try and a configurable socket timeout (`request_timeout`, seconds converted to milliseconds). Ports from its `IP -> [ports]` output must match the exact requested host and approved port set. Nmap is grouped per host with all discovered ports in a single call: `-sT -Pn -n -sV --version-light --max-retries 1 -T<network_timing> --max-parallelism <max_threads> --min-rtt-timeout <min(100ms, request_timeout)> --initial-rtt-timeout <min(1000ms, request_timeout)> --max-rtt-timeout <request_timeout> --host-timeout 0 -p <discovered> -oX -`. IPv6 adds `-6`. XML records with unexpected hosts, ports or transports are rejected. No NSE scripts or intrusive categories are used.

`app/network.py` supports HTTP Basic authentication. It pins DNS-checked sockets, verifies HTTPS certificates and requires an initial 401 Basic challenge. Its second request sends exactly one approved pair. Redirects are not followed, and arbitrary response bodies/headers are not stored as credential evidence. Outcomes are `not_attempted`, `not_supported`, `failed`, `successful`, `blocked` or `unknown`.

`app/capture.py` runs EyeWitness per approved endpoint with one thread and a scope proxy. The image patches the pinned browser factory; builds fail if the expected integration point changes. Each successful image is decoded and re-encoded as PNG, validated against artifact/pixel limits and accompanied by a thumbnail. Raw temporary reports are removed. Only HTTP/HTTPS on the exact approved origin is accepted by the proxy, including repeated DNS resolution checks. This can make pages missing third-party content look different, by design.

New tools should return structured observations and bounded execution metadata, accept a tick/cancellation callback, and enforce scope independently before network I/O. Never add a fallback that discovers or authenticates against out-of-scope targets. Future credential adapters must prove authentication reliably, detect defensive responses and preserve the same durable attempt journal and password-first ordering.


Subdomain mode uses Gobuster 3.6.0, compiled in a dedicated Go build stage. Its DNS adapter writes the validated relative labels to a private temporary wordlist and invokes `gobuster dns --domain <base> --wordlist <temporary-file> --show-ips --verbose --threads <max_threads> --timeout <request_timeout>s --quiet --no-progress --no-color`. There is no total duration limit. The timeout applies to each DNS lookup. The existing process guard, heartbeat and manual stop still apply. Streaming DNS stdout is not accumulated: line buffers and diagnostic stderr remain bounded, so a large volume of negative results does not exhaust the output cap. Negative DNS results are discarded; only exact approved names with resolved IP addresses are persisted. The operating system DNS resolver is used. Wildcard DNS is not forced: Gobuster errors and diagnostics are persisted as a failed run. Results must match an exact wordlist candidate under the approved base domain and contain valid IP addresses. The DNS wildcard probe is performed by Gobuster before enumeration.

The base domain and normalized wordlist are stored in the immutable run snapshot. DNS results are stored as `subdomain` findings and exposed through the paginated `/api/v1/runs/{id}/subdomains` collection. Progress counts completed wordlist names, including negative answers and failed resolutions. Gobuster verbose records are consumed incrementally: only positive observations are stored, negative records update the progress counter and are discarded. Progress is persisted at most every 0.5 seconds and each positive result is committed immediately; the final progress update is flushed even on stop or failure. A persisted DNS checkpoint prevents rerunning a completed enumeration after a pause. Gobuster errors fail the run and remain visible in Events. Existing scan configurations without a mode continue to use Network. No database migration is required.


Wordlists can be submitted as multipart uploads to `POST /api/v1/scans` or `PATCH /api/v1/scans/{id}`, with a JSON `config` field and a `wordlist` file part. Files must be UTF-8 text, up to 3 MiB, containing at least one name. There is no limit on the number of names. The API validates and normalizes names and stores them with the filename in the scan configuration, so workers do not need a shared upload directory and run snapshots remain immutable. The UI displays file metadata instead of inserting file contents into the manual textarea. Subsequent configuration edits omit the wordlist unless it is replaced. JSON requests remain supported for manual lists and existing clients. Nginx permits 4 MiB scan requests for multipart overhead and configuration; other routes retain the 64 KiB limit.


Timing configuration is stored in each definition and immutable run snapshot: `request_timeout` (0.001–300 seconds; default 2), `max_threads` (1–1024, default 10), and `network_timing` (Nmap T0–T5, default T3). Nmap's probe timeout is an RTT upper bound; service identification uses Nmap's own service-probe timing. Maximum threads means DNS workers for Gobuster, concurrent connections for RustScan, and outstanding port probes for Nmap; it does not parallelize target hosts or the optional HTTP modules. `--host-timeout 0` explicitly disables the implicit deadline in Nmap T5. The legacy `timeout` field is accepted for compatibility but ignored and omitted from new snapshots. The wordlist file size limit remains 3 MiB; there is no name-count limit.


Multipart import ignores blank lines and comment lines starting with `#`, `;` or `//`. It normalizes case, IDNA and trailing dots, converts full subdomains under the selected base domain into relative candidates, and removes duplicates. DNS candidates allow letters, digits, underscores and hyphens (including terminal hyphens), with labels up to 63 bytes. Base domains retain hostname validation. URLs, wildcard entries, unsupported literal escape sequences, the base domain itself and overlong candidates are skipped. The persisted `wordlist_import` report records counts and up to five invalid line examples with original line numbers, displayed on the scan definition page. An upload with no valid candidates is rejected with line details. Manually entered invalid candidates still produce a validation error that identifies the row.


The results UI polls while an enumeration runs: the progress bar shows names completed / normalized wordlist size (for example `15 / 5000`), and the Subdomains table refreshes every 1.5 seconds. Its final refresh also runs when polling stops, so results arriving just before completion or stop remain visible. Stopping a process preserves already committed positive results and the last completed-name count. A name may involve multiple A/AAAA DNS packets and retries; this counter measures names, not raw network packets.


Network target input separates bare hostnames (`hostnames`) from explicit endpoints (`urls`). The API also accepts bare names in `urls` and moves them into `hostnames`; the UI combines both in one editable field. Launch resolves both classes and freezes the same bounded IP scope. Bare hostnames do not create port-80 screenshot attempts unless Nmap identifies HTTP there. Open Nmap services named HTTP, HTTP-alt/proxy, HTTPS or HTTP under an SSL tunnel generate one endpoint for each appropriate hostname/port/scheme, without duplicate numeric-IP captures for those hostnames. Each screenshot's proxy scope pins the IP recorded for that endpoint while rechecking that all DNS answers stay inside the frozen scope and that the observed address is still present. HTTP ports on unnamed IP targets retain numeric-IP URLs. Per-endpoint capture failures do not prevent later ports from being attempted.


`GET /api/v1/runs/{id}/network-draft` prepares a read-only Network form draft from every positive `subdomain` finding in a DNS run, independently of result pagination/filters. It rejects non-DNS runs and empty result sets, supports partial runs, and returns source metadata with the prefilled configuration. No scan or run is created until the user saves/launches it. The form accepts the returned bare names in its URL/hostname field; there is no hostname-count limit, while the existing launch-time IP scope limit still applies. The original DNS run and results are unchanged.


Network launch returns HTTP 202 before resolving DNS. The worker runs `python -m app.prepare_scope <private-temporary-config>` through the process guardian, with no total deadline and the normal heartbeat/stop callback. The resolver child performs the existing scope checks and reports the effective configuration plus individual DNS issues as JSON. Only after successful preparation does the worker freeze IPs into the run snapshot and persist its `scope/prepared` checkpoint. Scope failures become failed runs with diagnostics and never start port scanning. This avoids HTTP 504s when importing many DNS recon names or when the system resolver is slow, without extending proxy timeouts. Pending runs initially contain the approved input configuration; prepared/resumed runs use the finalized effective snapshot.
