# Security and threat model

HackingBara trusts the authenticated operator to approve a scope, but treats all targets, DNS answers, scanner output, banners and browser content as hostile. It is a sensitive network client, not a multi-tenant public scanning service. Accounts have identical capabilities, including scan deletion and approved credential validation.

## Boundaries

- Local accounts use Argon2id. Session cookies are HttpOnly, Secure by default, SameSite Strict, randomly generated and stored as SHA-256 hashes. CSRF tokens are separately random and hashed in the session. Mutations require both the token header and the configured exact Origin. Login also requires Origin. Sessions expire after 12 hours and logout revokes them immediately. Login attempts are throttled in PostgreSQL (10 failed attempts per peer IP per 15 minutes). Behind the bundled proxy, clients share that peer budget; configure trusted proxy identity deliberately before changing this policy.
- Credential passwords use Fernet authenticated encryption with an external key. API serialization excludes both plaintext and ciphertext. Validation errors omit input values. Referenced credentials are immutable. Bootstrap passwords are entered interactively; no default account exists. Keep `.env` and the encryption key outside Git.
- A definition may contain IP/CIDR targets, bare hostnames, explicit URLs, or a combination. For a hostname/URL-only definition, explicit launch authorization includes the IPs resolved from the supplied URLs; the worker resolves/deduplicates them in its scope stage and freezes the bounded address set before port scanning without changing the definition. The HTTP launch endpoint only validates and queues the approved input. When IP targets are supplied, they remain the scope and DNS cannot extend it. A run snapshots the resulting approved IP/CIDR scope, hostnames and URLs. Nmap-discovered web endpoints retain supplied hostnames for virtual hosting; screenshot connections pin the observed service address while preserving the original hostname and checking current DNS answers against the frozen scope. Limits are enforced before CIDR expansion. RustScan receives numeric IPs and validated port lists, with scripts disabled. Nmap receives only discovered TCP ports, numeric hosts, no DNS, TCP connect mode, version-light and no NSE. XML entities are forbidden.
- After launch, every URL DNS answer must still lie inside the frozen run scope, including when addresses originally came from URLs. Connections pin the checked numeric IP, preserve HTTP Host, and preserve SNI/certificate validation for credential HTTPS connections. The credential adapter never follows redirects, requires a Basic challenge before sending a secret and never infers success from a public page. HTTP Basic on plaintext HTTP is supported only when the operator explicitly approves that URL; prefer HTTPS for actual accounts.
- Password-first ordering uses only approved pairs. Budgets apply globally per username per run, and per HTTP authority (host/port), across multiple paths. Attempts are journaled before I/O. Defensive responses, uncertain errors and lockouts halt that service; completed or uncertain attempts are never retried on resume. Validation of unknown protocols remains unsupported.
- EyeWitness is optional at both administrator and scan level. Its browser options require a run-local proxy, disable direct proxy bypass including loopback, disable QUIC and non-proxied WebRTC, and disable background networking/extensions. The proxy accepts read-only HTTP and approved HTTPS CONNECT, checks the exact approved origin, resolves all addresses into scope and connects to a pinned address. It blocks out-of-origin redirects and resources. TLS tunnels cannot inspect HTTP paths; all paths of the approved HTTPS origin are allowed. Screenshot browser certificate errors are tolerated by upstream EyeWitness; screenshots are evidence, never authentication proof. EyeWitness preflight requests use the same proxy through environment configuration. The Selenium control connection bypasses environment proxies locally.
- The proxy is application-level defense, not a browser security sandbox. A browser exploit or upstream EyeWitness code change could defeat it. The pinned EyeWitness revision and mandatory browser patch reduce accidental bypass. Deploy worker egress filtering on the host/network to permit only approved assessment subnets and required database/Redis/DNS traffic when assessing hostile pages. Do not add broad capabilities or privileged mode. The API and data services have no scanner egress network. Target hostname resolution runs in the worker with its DNS connectivity; the API has no published host port. Administrators can restrict API egress to required infrastructure with host policy. Protect metadata and infrastructure addresses by excluding them from approved scopes and enforcing worker egress policy.
- Subprocesses use argument arrays, bounded output, deadlines, a separate process group, a parent-death guardian and graceful-then-forced cancellation. No credentials appear in argv. Tool failures preserve observations; a stale worker lease fails closed. External scanner error details intentionally omit arbitrary exception strings. Untrusted banners are rendered as escaped Vue text, never `v-html`.
- Screenshot paths are generated internally; content endpoints verify paths remain under the evidence root and require a valid session on every request. Only validated PNG images and thumbnails are retained; size/pixel limits apply. No public static evidence directory exists. Same-origin fetch, restrictive frontend CSP and frame protection are configured. API docs also require login.

## Operations

Terminate TLS before exposing the UI beyond loopback; set an exact HTTPS `PUBLIC_ORIGIN` and keep `SECURE_COOKIES=true`. Configure HSTS at the TLS endpoint. Keep the Docker daemon private. Containers run as non-root where practical; capabilities are dropped and no-new-privileges is enabled. The scanner uses TCP connect scanning, so NET_RAW and host networking are unnecessary. Browser resource consumption is bounded by single-target execution, worker concurrency, process deadlines and container memory/CPU limits.

Monitor disk usage and delete completed scans to enforce your retention policy. Scan deletion removes its observations and evidence, but retains persistent inventory. A filesystem deletion failure may leave inaccessible orphaned files; monitor storage and clean those files during maintenance. Database/evidence backups contain sensitive network information even without plaintext credentials. Restoring a database without its encryption key cannot restore credential usability.

Known limits: no MFA, per-user isolation, antivirus processing of scanner artifacts, automatic credential revelation, automatic retention, distributed orchestration or network firewall management. Database session cleanup is administrative; expired tokens cannot authenticate. If a worker is frozen rather than dead, lease expiration revokes ownership and the next subprocess tick cancels work; hard host failures require the host/container runtime to terminate the worker namespace. DNS resolution uses the system resolver and its configured timeout policy. The UI's live transport is authenticated polling rather than SSE.
